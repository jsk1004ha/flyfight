# FlyFight Native 0.2 — Python 학습 + HTML 관전

**2026년 9월 제작. 실제 FlyWire/BANC 커넥톰이 아니라 합성 순환 신경망을 사용하는 실행형 개발 버전입니다.**

브라우저 한 탭이 물리·관측·학습·그리기를 모두 담당하던 이전 버전에서, 학습을 별도 Python/PyTorch 프로세스로 옮겼습니다. HTML은 총을 든 3D 초파리 두 마리, 실제 계산한 내부 활성, 각자의 시야를 표시합니다. 맵은 **64 × 48 게임 단위, 엄폐물 16개**로 확장했습니다.

CUDA 경로를 구현했지만 이 배포본의 실행 검증 환경에는 CUDA가 없었습니다. RTX 5090 성능, 기존 HTML 대비 가속 배수, 플레이 실력 향상은 검증하지 않았습니다. 초기 가중치에서 시작하므로 곧바로 능숙한 전투가 나타난다는 뜻이 아닙니다.

최근에는 `--action-steps 9|17|33|65`로 조준 간격을 0.25부터 0.03125까지 선택할 수 있고, `--convert-schema2`로 이전 체크포인트의 공통 가중치를 새 액션 헤드에 옮길 수 있습니다. 실제 Chrome/WebSocket/학습 동시 성능은 `live_benchmark.py`로 측정합니다. 공식 MaleCNS v1.0 데이터 변환 현황은 [MALECNS_INTEGRATION_KO.md](MALECNS_INTEGRATION_KO.md)를 참고하세요.

## 1. 실행 — Windows / WSL

소수점 세 자리 조준과 헤드샷 보너스를 사용하는 새 학습:

```powershell
python run.py --action-precision 3 --turn-speed 1.234 --pitch-speed 0.567 --headshot-bonus 0.25 --open-browser
```

`--action-precision 2`는 0.01, `3`은 0.001 간격이며 `--action-steps`보다 우선합니다. 값은 −1~+1의 정규화된 조준 명령입니다. 실제 각도 변화(rad)는 명령 × 회전 속도(rad/s) × dt입니다. 속도는 양수 20 이하, 헤드샷 보너스는 0~10을 받습니다. 기본 액션 단계는 기존 9단계를 유지합니다. 3자리 모드는 축마다 2001가지 선택지를 학습하므로 학습 속도/실력 향상을 보장하지 않습니다.

새 학습의 헤드샷 보너스 기본값은 0.25로, 단독 헤드샷 처치 시 +1.25 / −1.25입니다. 동시 헤드샷은 상쇄됩니다. 승패 집계에는 기본 결과만 사용합니다. 재개 시 액션 단계·속도·보너스가 저장값과 같아야 하며, 보너스 필드가 없는 구형 체크포인트는 `--headshot-bonus 0`을 지정합니다.

Python 3.12 환경을 사용할 수 있습니다. 이미 GPU가 정상 인식되는 PyTorch 환경이 있으면 그 환경을 그대로 사용하세요. `requirements.txt`는 기존 CUDA 빌드를 교체하지 않도록 **torch를 설치하지 않습니다**. 실행 검증은 Linux Python 3.13 + PyTorch 2.10.0+cpu에서 했습니다. Windows 배치 파일 자체는 Windows에서 실측하지 않았습니다.

ZIP을 풀고 `run.py`가 있는 폴더에서 실행합니다.

```powershell
python -c "import torch; print(torch.__version__); print('CUDA:', torch.cuda.is_available()); print(torch.cuda.get_device_name(0) if torch.cuda.is_available() else 'CPU only')"
python -m pip install -r requirements.txt
python run.py --device cuda --envs 128 --open-browser
```

첫 명령에서 GPU 이름과 `CUDA: True`가 나오면 됩니다. torch가 없거나 CUDA가 False이면 PyTorch 공식 설치 선택기에서 해당 OS와 CUDA용 패키지를 선택하세요. RTX 5090에 구형 CPU 전용 wheel을 설치하지 마세요. 설치 안내는 아래 공식 참고 자료에 있습니다. 특정 CUDA 툴킷을 무조건 다시 설치하라는 의미가 아닙니다.

설치가 끝난 환경에서는 `START_WINDOWS.bat`를 더블클릭해도 됩니다. 해당 폴더의 `.venv`가 있으면 우선 사용하고, 없으면 PATH의 python을 사용합니다. 자동 선택은 CUDA가 없으면 CPU로 내려갑니다. **GPU 사용을 반드시 요구하려면 위의 `--device cuda` 명령을 쓰세요.**

브라우저 주소:

```text
http://127.0.0.1:8765
```

서버가 제공하는 이 주소로 열어야 토큰을 포함한 HTML↔Python 연결이 자동 설정됩니다. `viewer/FlyFight_Viewer.html` 파일만 더블클릭하면 큰 맵의 기존 합성 데모만 실행되며, 네이티브 학습이 시작되지 않습니다. 기본 서버는 보안상 file:// 출처의 수동 WebSocket 연결도 허용하지 않습니다.

CPU로 기능만 확인할 때:

```powershell
python run.py --device cpu --envs 8 --hidden 256 --horizon 16 --open-browser
```

또는 `START_CPU_WINDOWS.bat`를 실행합니다. 이 설정은 모델 크기도 바꾼 별도 실험입니다. 기본 768유닛 CUDA 설정과 동일한 성능 비교에 사용하면 안 됩니다.

WSL에서는 같은 Python 명령 또는 `bash start_wsl.sh`를 사용합니다. 자동 브라우저 열기가 지원되지 않으면 터미널에 출력된 주소를 브라우저에서 여세요. 서버는 로컬 전용으로 작성했으며 인터넷 공개 배포 설정은 포함하지 않습니다.

## 2. 무엇이 어디서 실행되는가

```text
Python 학습 프로세스 — 선택한 CPU 또는 CUDA 장치
  ├─ 128개 병렬 경기의 물리 / 충돌 / 명중 판정
  ├─ 각 개체의 24×16 RGB 시야 생성
  ├─ 독립 모델 A와 B의 행동 추론
  └─ recurrent PPO로 입력층·순환층·정책·가치함수 학습
            │ 주기적 정책 스냅샷 / 최신 지표
            ▼
Python 서버 — CPU에서 별도 관전 경기 추론
  ├─ 실제 관전 경기의 위치·발사·상태
  ├─ 그 경기에서 실제 계산한 신경망 활성
  └─ 정책이 실제로 받은 RGB 픽셀
            │ WebSocket
            ▼
HTML — 3D 초파리 / 큰 맵 / 활성 패널 / 실제 시야
```

**128개 경기마다 서로 다른 뇌를 영구적으로 키우는 방식은 아닙니다.** 학습 모델은 독립적인 A와 B 두 개이며, 각 모델이 병렬 경기의 경험을 모아 학습합니다. A와 B는 초기 가중치는 같지만 파라미터·옵티마이저·경험·순환 상태를 서로 공유하지 않습니다. 에피소드가 끝나면 순환 상태를 지웁니다.

GPU 계산 경로에는 고해상도 브라우저 렌더링, 스크린샷 전송, 브라우저 응답 대기가 들어 있지 않습니다. 많은 경기의 물리와 RGB 계산은 PyTorch 텐서 배치 연산입니다. 관전 데이터와 학습 데이터 전송은 유한 큐를 사용하며 느린 관전 클라이언트 때문에 프레임이 무한 누적되지 않게 했습니다. 모델을 CPU로 복사하는 시점에는 비용이 발생하므로 이 구조가 비용 0이라는 뜻은 아닙니다.

관전 화면은 **빠르게 학습 중인 128개 경기 중 하나를 그대로 생중계하는 것이 아니라, 최신 스냅샷으로 실행하는 별도 경기**입니다. 이 경기의 경험은 학습하지 않습니다. 새 가중치는 다음 라운드 시작 때 적용해 한 라운드 중 신경 상태와 모델이 뒤섞이지 않게 했습니다. 따라서 화면의 `v...` 정책 버전은 학습 UPDATE보다 늦을 수 있습니다.

HTML을 닫거나 관전을 멈춰도 학습은 계속됩니다. 연결된 관전자가 없으면 관전용 RGB 계산도 쉽니다. 프로그램 자체를 종료하려면 터미널에서 Ctrl+C를 누르세요. 현재 업데이트를 마치고 체크포인트를 저장한 뒤 종료하므로 즉시 끝나지 않을 수 있습니다.

## 3. 학습 규칙 — 전술을 넣지 않음

정책과 가치함수의 입력은 **자신의 RGB 영상 + 직전 행동 5채널**뿐입니다. 적 좌표·거리·방향, 엄폐물 좌표, 명중 여부, 최단경로, 관전자 카메라, 맵 조감도는 입력하지 않습니다. 환경은 충돌·명중·가림을 계산하기 위해 좌표를 사용하지만 정책에는 제공하지 않습니다.

출력은 이동 5종(정지/전진/후진/좌/우), 회전 9종, 상하 시점 9종, 발사 2종의 범주형 행동입니다. 회전과 시점은 `-1.00`부터 `+1.00`까지 0.25 간격으로 디코딩됩니다. 조작과 게임 결과의 관계는 환경에 정의되어 있습니다. “아무 정보도 없는 존재”가 아니라 **조작 인터페이스와 승패 목표는 주어지고, 전술·시범·정답 행동을 주지 않는 학습**입니다.

승리 +1, 패배 −1, 동시 사망 또는 시간 초과 무승부 0입니다. 헤드샷은 100 피해로 즉시 처치하고 몸통 명중은 34 피해이므로 세 발에 처치되며, 탄약은 무한, 연사 제한 0.4초, 기본 라운드는 60초입니다. 접근·생존·조준·이동·일반 명중·헤드샷 횟수에 대한 추가 보상은 없습니다. 초기 방향도 적을 향하도록 맞추지 않습니다.

학습 알고리즘은 순환 PPO + GAE + 잘린 시간 역전파입니다. 출력층만 갱신하던 이전 버전과 달리 입력층·순환층·정책 출력·가치함수 파라미터를 모두 갱신합니다. 엔트로피 항은 행동 분포의 탐색을 위한 명시적 최적화 정규화항이며 게임 보상이 아닙니다. 생물학적 도파민, STDP 또는 실제 초파리 시냅스 가소성을 구현한 것이 아닙니다.

상대도 계속 바뀌기 때문에 최신 A/B의 상대 승률만으로 전체 실력이 향상됐다고 볼 수 없습니다. 이번 버전에는 과거 상대 풀·리그·Elo 시스템·자동 커리큘럼이 없습니다.

## 4. 큰 맵과 시각화

맵은 `maps/arena_large.json` 한 곳에서 정의합니다. 기본 크기는 64×48, 외벽 높이 5, 내부 엄폐물 16개입니다. 중앙 교전 구역과 측면 우회 공간, 높이가 다른 엄폐물을 배치했습니다. 게임 단위이므로 실제 미터나 초파리 실물 크기로 해석하지 마세요.

네이티브 환경과 관전기는 같은 맵 정의를 사용합니다. 서버의 `hello` 메시지가 해당 맵을 전달하므로 외부 지도와 화면이 별개로 바뀌지 않습니다. 다만 충돌은 단순화된 몸체로 판정하며 세밀한 다리·날개 메시는 장식입니다. 이동은 지면상의 2차원, 시선과 광선 판정은 3차원입니다. 비행·점프·탄도·파괴 가능한 지형은 없습니다.

카메라: 결투 추적 / 전체 맵 / A 추적 / B 추적 / 탑뷰. 드래그·휠로 회전·확대도 가능합니다. 전체 맵에서는 초파리가 작게 보이는 것이 정상이며 결투 추적 또는 개체 추적으로 확대할 수 있습니다.

하단 시야는 두 모드를 지원합니다.

- **실제 입력**: Python의 24×16 RGB 영상 원본. 학습기는 상자·바닥·상대의 구형 충돌체를 광선 교차로 그립니다. 적 좌표를 색상 채널로 넣는 등의 특권 정보가 아니라 시야 안에서 가려짐을 반영한 렌더링입니다.
- **상세 3D**: HTML에서 복원한 날개·다리·총이 있는 관전 장면. 더 보기 좋지만 정책에 들어간 픽셀과 같지는 않으며 화면에 이를 표시합니다.

신경 패널의 밝기는 관전 정책의 실제 `abs(h)`입니다. 스파이크·mV·Hz로 표기하지 않습니다. 좌우 엽과 하부 구조의 앞뒤 깊이를 확대한 **뇌 형태의 모식 배치**이며 실제 생물학적 해부 좌표가 아닙니다. 기본 768유닛부터 지원 최대 크기인 4,096유닛까지 모델의 모든 유닛을 표시합니다. 표시 연결선은 전체 연결의 고정 표본입니다. `연결` 버튼은 표시 표본의 활성/전체/숨김, `점` 버튼은 M/L/S, `−/＋`와 휠은 확대·축소를 조절합니다. 드래그로 회전하고 점을 클릭하면 유닛 ID와 실제 부호 있는 hidden 값, 절댓값을 고정 표시합니다. 부호 값을 제공하지 않는 외부 스트림은 미제공으로 표시합니다.

학습 계산을 시간축으로 묶는 최적화와 CPU 실측, GPU/배치/해상도/기억 길이별 실험 방법은 [LEARNING_TUNING_KO.md](LEARNING_TUNING_KO.md)에 있습니다. 이번 최적화는 스키마 3 모델 크기를 유지하며 기본 적용됩니다.

각 프레임은 행동 결정 직전의 시야/활성(`input_t`)과 행동 적용 직후의 물리 상태(`t`)를 함께 보냅니다. 1 제어 스텝의 시차가 있으며, 화면에 두 시각을 표시합니다. 이를 완전히 동일 시점의 측정이라고 해석하지 마세요.

## 5. 저장·중단·재개

기본 실행 디렉터리는 `runs/session_YYYYMMDD_HHMMSS`입니다. 기존 실험을 실수로 덮어쓰지 않도록 동일 폴더에 새 실행을 시작하면 거부합니다. 자동 저장은 기본 50 업데이트마다, 정책 관전 전송은 10 업데이트마다입니다.

```text
runs/session_.../
  config.json       설정
  initial.pt        학습 전 비교 기준
  latest.pt         모델·옵티마이저·환경·난수·순환 상태
  metrics.jsonl     학습 처리량·업데이트·결과 기록
  error.log         오류가 발생했을 때만 생성
```

화면의 ‘학습 일시정지’는 실제 학습을 멈추고 ‘모델 저장’은 현재 체크포인트 저장을 요청합니다. 관전 재생 버튼과는 별개입니다. 저장 버튼 응답은 **요청 수락**이지 디스크 기록 완료 확인이 아니며 진행 중인 업데이트 뒤에 저장됩니다. 학습 일시정지 상태에서도 저장됩니다.

액션 헤드가 9단계로 확장되어 체크포인트 스키마가 3으로 올라갔습니다. 이전 5/3단계 액션 스키마로 만든 체크포인트는 출력층과 옵티마이저 크기가 달라 재개할 수 없으므로 새 실행 디렉터리에서 시작해야 합니다. 기존 체크포인트 파일은 삭제하거나 덮어쓰지 않습니다.

기본 128환경·768유닛 설정을 재개하는 예:

```powershell
python run.py --device cuda --envs 128 --resume runs/session_20260915_210000/latest.pt --open-browser
```

예시 경로를 실제 폴더명으로 바꾸세요. 재개할 때 환경 수, hidden, width, height, dt, episode-seconds, seed와 맵 내용은 기존과 같아야 합니다. 처음 CPU 기능 확인 옵션을 사용했다면 해당 옵션도 똑같이 지정해야 합니다. 정확한 재현은 같은 장치·설정에서 평가해야 합니다. CPU에서 저장/재개 후 다음 업데이트가 동일한지 검사했지만 CUDA 간 비트 단위 재현은 검증하지 않았습니다. 신뢰할 수 없는 체크포인트를 실행하지 마세요.

## 6. 성능 측정과 조절

기본 `--envs 128`은 시작 설정이며 RTX 5090에서의 최적값을 실측한 값이 아닙니다. 아래 스크립트는 워밍업 후 실제 물리·RGB·두 정책 추론·PPO 역전파 전체의 환경 스텝/초를 측정합니다.

```powershell
python benchmark.py --device cuda --envs 128 --updates 10 --output benchmark_128.json
python benchmark.py --device cuda --envs 256 --updates 10 --output benchmark_256.json
```

두 결과의 처리량과 GPU 메모리를 비교하세요. OOM이 발생하면 환경 수를 줄여 새 실험으로 시작합니다. 해상도·hidden·horizon을 바꾸면 메모리뿐 아니라 모델과 학습 문제 자체도 달라집니다. 동일 조건의 성능 비교에서는 바꾸지 마세요.

`env_steps_s`는 각 병렬 환경 스텝 수의 합을 벽시계 시간으로 나눈 값입니다. 각 환경에 두 에이전트가 있으므로 `agent_decisions_s`는 그 2배입니다. 화면 FPS, 라운드 수/초, 게임 실력과 혼동하지 마세요.

뷰어 렌더 목표는 60 FPS입니다. 브라우저가 48 FPS 아래에 머물면 내부 렌더 해상도를 단계적으로 낮추고, 여유가 회복되면 다시 올립니다. 하단 `배속` 버튼 또는 `B` 키는 1×/4×를 전환하며 선택 상자에서 0.5×, 1×, 2×, 4×, 8×를 고를 수 있습니다. 네이티브 관전은 시뮬레이션 배속과 WebSocket 전송 주기를 분리해 8×에서도 브라우저 전송을 최대 30 FPS로 제한합니다. 배속은 별도 관전 경기에만 적용되고 학습 처리량을 바꾸지 않습니다.

옵션 `--amp`는 CUDA BF16 혼합 정밀도, `--compile-policy`는 정책의 torch.compile 경로입니다. 기본은 둘 다 꺼져 있습니다. 설치 환경에 따른 컴파일 지원과 초기 준비 비용이 있으므로 각자 별도로 벤치마크한 뒤 사용하세요. CUDA/AMP/compile 실행은 이번 CPU 검증에 포함되지 않습니다. Python→PyTorch 변경만으로 속도 개선을 보장할 수 없습니다.

순수 학습만 할 때:

```powershell
python run.py --device cuda --envs 128 --headless
```

이 모드는 서버를 시작하지 않습니다. 실시간 HTML 관전이 필요하면 `--headless`를 빼세요.

## 7. 실력 검증

고정된 초기 정책과 비교하는 스크립트를 제공합니다. 후보 A는 초기 B와, 후보 B는 초기 A와 대결하며 진영을 번갈아 배정합니다. 평가 중 학습하지 않습니다.

```powershell
python evaluate.py --checkpoint runs/session_.../latest.pt --opponent runs/session_.../initial.pt --identity A --games 256 --envs 32 --device cuda --output eval_A.json
python evaluate.py --checkpoint runs/session_.../latest.pt --opponent runs/session_.../initial.pt --identity B --games 256 --envs 32 --device cuda --output eval_B.json
```

여러 seed·여러 시점의 고정 상대에 대해 반복하세요. 출력에는 승·패·무승부, 전체 경기 기준 승률, 결정된 경기만의 승률, Wilson 구간을 구분합니다. 경기가 서로 상관될 수 있어 단일 Wilson 구간이 모든 불확실성을 나타내지는 않습니다.

맵 확장은 상대 조우를 줄일 수 있고 희소 보상 학습을 어렵게 만들 수 있습니다. 무승부가 대부분이면 “학습이 진행됐다”만으로 조준이나 전략을 배웠다고 결론 내리지 마세요. 이번 실행 검증에서 작은 모델의 4경기 평가 스모크 테스트는 **4무승부**였으며, 성능 개선 증거가 아닙니다. 의도한 무지식 조건을 유지하기 위해 명중 보상·조준 보정·강제 근접 스폰·자동 쉬운 맵 전환을 추가하지 않았습니다.

## 8. 검증 범위

이번 배포에서 실제 실행한 검증:

| 구분 | 결과 | 범위 |
|---|---:|---|
| 핵심/추가 단위 테스트 | 26 통과 | 전투·체크포인트·시퀀스 출력/기울기 동등성·학습 통계·1536유닛 표시 |
| 브라우저 테스트 | 41 통과 | FPS·배속·뉴런 확대/크기/연결선/선택·signed 활성·카메라·헤드샷·입력 검증 |
| 실제 HTTP/WebSocket 통합 | 18 통과 | 인증·맵/활성/RGB 수신·학습/관전 분리·8배속·저장·연결 종료 뒤 학습 |
| 768유닛 기본 차원 모델 | CPU 실행 확인 | 24×16 입력, 두 에이전트의 학습/관전 루프 |
| 평가 CLI | 실행 확인 | 작은 테스트 모델, 4경기 전부 무승부 |

로그와 결과 JSON은 `evidence/`에 있습니다. 브라우저는 설치된 시스템 Chrome의 Chromium/WebGL2에서 검사했고 렌더 루프 표본은 약 60 FPS였습니다. 브라우저 자동 검사는 **HTML을 set_content로 로드하고 실제 서버에서 받은 프레임을 문서화된 ingest API로 넣어 렌더링**했습니다. 실제 HTTP/WebSocket은 별도의 aiohttp 클라이언트로 검증했습니다. 따라서 이 표본은 사용자 PC의 보장 FPS가 아니며, ‘실제 브라우저 소켓을 포함한 end-to-end’, Windows 더블클릭, RTX 5090 GPU 가속이 모두 검증됐다는 뜻도 아닙니다.

CPU 소규모 배치(8환경·768유닛·24×16·horizon8)의 로컬 벤치마크도 포함했습니다. 제한된 공유 실행 환경에서 얻은 값으로 사용자 PC의 처리량이나 이전 HTML 대비 가속 배수로 해석하지 마세요.

재실행:

```bash
python -m pip install -r requirements-dev.txt
python -m pytest -q tests/test_core.py
python tests/transport_check.py
python tests/browser_check.py
```

마지막 브라우저 테스트는 Playwright Chromium이 필요합니다. Linux의 이번 검증 명령은 `xvfb-run -a python tests/browser_check.py`였습니다. `CHROMIUM_PATH` 환경 변수로 브라우저 실행 파일을 지정할 수 있습니다. transport 테스트는 Linux CI용으로 작성했으며 Windows에서는 종료 시그널 처리가 다를 수 있습니다.

## 9. 소스 구조와 경계

```text
run.py                      학습/서버 시작
benchmark.py                사용자 장치의 실제 처리량 측정
evaluate.py                 고정 상대 성능 검증
flyfight/environment.py     벡터화 물리와 RGB ray caster
flyfight/model.py           합성 leaky RNN, actor, critic
flyfight/training.py        독립 recurrent PPO, 저장/재개
flyfight/spectator.py       별도 관전 경기, 실제 활성/픽셀
flyfight/server.py          로컬 HTTP/WebSocket, 제어 분리
maps/arena_large.json       단일 맵 원본
viewer/src/                 기존 그래픽 엔진을 확장한 소스
viewer/FlyFight_Viewer.html 묶인 관전기/단독 합성 데모

```

프런트 소스 또는 기본 맵을 수정하면 `python build_viewer.py`로 단독 HTML도 다시 만드세요. 네이티브 실행은 서버가 map JSON을 직접 전송합니다. 학습 중 맵 파일을 바꾸지 마세요. 맵을 바꾼 뒤에는 새 실험 디렉터리를 사용해야 합니다.

실제 초파리 연구로 확장하려면 합성 RNN을 실제 커넥톰 연결·뉴런 ID·동역학·학습 규칙으로 교체하는 별도 작업이 필요합니다. **현재 모델의 hidden을 14만으로 늘리는 것은 실제 초파리 뇌 구현도 아니고 적절한 최적화도 아닙니다.** 실제 커넥톰 학습기·데이터 수집·생물학적 검증·근육 역학은 이번 파일에 포함되지 않습니다.
